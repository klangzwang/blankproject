# Coding and change conventions

1. Inspect before creating: search for existing classes, stubs, utilities, registrations, loaders and resources.
2. Extend the existing implementation instead of creating duplicates.
3. Keep a task scoped to the correct area and only touch necessary files.
4. Do not change resources or project configuration without a task-specific reason.
5. Do not infer missing APIs. Inspect dependency versions and usages; ask if uncertainty remains.
6. Report unsupported behavior and incomplete compatibility honestly.
7. Run relevant tests/build/type checks and report exactly what was and was not verified.
8. Preserve original source documents and project data unless explicitly asked to remove or replace them.
